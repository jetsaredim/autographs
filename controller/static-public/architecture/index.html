Autographs system overview

GitHub validates changes and deploys released controller images. Cloudflare handles authoritative DNS, HTTPS proxying, and caching of public media. OCI runs Caddy, the static public site, Rust private controller, Autonomous Database, private Object Storage media, and Vault secrets.

Workflow step definitions

Step Workflow Definition
1Validate changesPull requests run application, infrastructure, and workflow checks. Terraform plans wait for the shared OCI state lock when another plan or deployment is using it.
2Release and deployOrdinary merges accumulate in a release-please PR. Merging that release PR triggers the production workflow, which publishes the controller image to GHCR and deploys through Terraform and Ansible.
3Manage DNS and edge rulesPorkbun delegates the domain to Cloudflare nameservers. A controlled Terraform workflow manages the Cloudflare DNS zone and proxy rules.
4Serve public trafficPublic visitors reach Cloudflare's proxied route over HTTPS. Caddy serves the generated static content from a Podman volume on the runtime VM.
5Separate admin and public routesCloudflare caches fingerprinted public image derivatives while keeping HTML and JSON fresh. Admin HTTPS requests pass through Cloudflare without caching and continue to the VM's Caddy and Rust controller.
6Manage contentThe private admin shell calls the Rust controller for item editing, media adjustments, and publishing. Caddy routes admin requests to that controller.
7Access private dataThe controller reads and writes Autonomous Database catalog metadata and private Object Storage originals. The publisher generates public-safe derivatives and releases.
8Retrieve secretsThe runtime uses its OCI instance principal to retrieve controller secrets from OCI Vault. The database password is generated by OCI and stored in Vault.
9Secure origin HTTPSCaddy obtains and renews its origin certificate with Let's Encrypt. Cloudflare connects to the origin using Full (strict) TLS validation.
