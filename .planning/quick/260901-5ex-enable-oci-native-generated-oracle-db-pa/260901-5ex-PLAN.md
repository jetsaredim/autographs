# Quick Task 260901-5ex: Enable OCI-Native Generated Oracle DB Password Rotation

<objective>
Configure OCI Secret Management to generate and rotate the Autonomous Database ADMIN password, coordinated with the existing ADB, while preserving current resource identities and the controller's already-proven credential-refresh behavior.

Purpose: Remove operator-generated database-password material and make scheduled rotation safe, observable, and recoverable without application restarts or new boolean state controls.

Output: An in-place Terraform rotation contract, focused regression coverage, updated bootstrap guidance, and a guarded on-demand production validation procedure.
</objective>

<locked_decisions>

- **D-01:** Both the secret and ADB remain managed by the deployment Terraform state.
- **D-02:** Break the resource cycle with an in-root exact-name lookup of the existing database-password secret for ADB; the managed secret may reference the managed ADB as its rotation target.
- **D-03:** Only `oracle_db_password` is generated/rotated; wallet password and admin hash remain operator-managed.
- **D-04:** Generation is `PASSPHRASE` / `DBAAS_DEFAULT_PASSWORD` / length `30`.
- **D-05:** Scheduled rotation is enabled with interval `P90D`.
- **D-06:** Terraform configures but never invokes rotation; live acceptance uses OCI on-demand rotation, controller refresh evidence, and incremental publish without restart.
- **D-07:** Add no operator-maintained boolean and never recreate, import, state-move, print, or persist the existing secrets or their contents.

</locked_decisions>

## Trust Boundaries

| Boundary | Description |
|---|---|
| Terraform deployment identity → OCI Vault/ADB control plane | Compartment-scoped automation configures generation and coordinated rotation but must never receive secret content. |
| OCI Vault → Autonomous Database | OCI rotation changes the ADMIN credential in both systems; target mismatch or overlapping operations can interrupt database access. |
| Runtime instance principal → Vault CURRENT bundle | The controller may read only its named secret bundles and refreshes the DB password only after exact invalid-credential failure. |
| Operator workstation → OCI CLI/production VM | Live acceptance handles OCIDs, versions, work requests, and logs; content and plaintext are forbidden. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-5EX-01 | Information Disclosure | Terraform state, CLI, logs, docs | mitigate | Generate in OCI, omit DB `secret_content`, never fetch bundles during validation, and assert no plaintext/password input or pinned version. |
| T-5EX-02 | Tampering | Secret-to-ADB rotation target | mitigate | Exact-name single-result lookup, managed ADB OCID target, provider validation, and a completed OCI work request before acceptance. |
| T-5EX-03 | Denial of Service | ADB ADMIN credential rotation | mitigate | Stop on destructive/unrelated plans, do not overlap scheduled/on-demand rotations, verify ordinary DB health first, and prove refresh plus incremental publish without restart. |
| T-5EX-04 | Elevation of Privilege | Deploy/runtime OCI identities | mitigate | Reuse existing compartment-scoped deploy management and stable-name runtime bundle-read policies; add no tenancy-wide or runtime rotation permission. |
| T-5EX-05 | Repudiation | Live rotation evidence | mitigate | Record numeric before/after versions, OCI terminal status/times, privacy-safe controller refresh log, publish result, and unchanged service start timestamp. |
