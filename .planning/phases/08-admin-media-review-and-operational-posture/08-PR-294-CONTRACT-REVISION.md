# PR #294: public media commit and emergency takedown contract

## Outcome and invariants

Implement `CR-02` (`candidate_media_precommit_exposure`, a `CR-01` fix regression) and `WR-02` (`emergency_media_takedown_retention`, a sibling consumer miss) as one release/media contract. An anonymously served `/media/*` response must come from an already committed release, except for a previously committed fingerprint retained for fresh documents and rollback. A candidate-only URL is absent before the `current` pointer changes, even if validation has passed or promotion fails. New active media is immediately reachable through Caddy's `current/media` fallback; old fingerprints remain available in shared media for at least 86,400 seconds after last active publication and while a retained release references them. An exact emergency tombstone overrides both serving locations and all retention or rollback copies. Candidate validation refuses a tombstoned URL before promotion. Public output remains free of private identifiers and adjustment metadata. Preserve the round 1 WebP byte/fingerprint and decoded-dimension checks (`WR-01`). Normal adjustment and unpublish retain the no-routine-Cloudflare-purge rule; emergency removal requires exact CDN purge.

The commit boundary is the existing atomic `current` symlink rename in `promote_candidate`. Candidate validation authorizes content, but the pointer change authorizes public visibility. Shared media is a retention namespace, never a candidate staging namespace. The durable marker mapping is `${AUTOGRAPHS_STATIC_RELEASE_ROOT}/.media-tombstones/media/<item-slug>/<image-slug>-<variant>-<16-hex-fingerprint>.webp` for exactly the requested `/media/...webp` URL. Marker files are empty regular files outside `current`, `releases`, `media`, and candidate manifests; no publisher cleanup deletes them. Both Caddy sites use the mounted static volume and test this path before shared or `current/media` lookup. Neither the marker path nor private release directory is web reachable.

## Ordered implementation

### 1. Make promotion the sole candidate visibility boundary

**Files:** `controller/src/publisher.rs`, `controller/tests/publisher.rs`.

1. Keep `build_candidate` and `validate_candidate`'s completeness, WebP fingerprint, and privacy checks. Add a root-aware check over the validated manifest's media artifact paths against exact-path tombstones. Require normal `media/...webp` components, a regular marker or no marker, and explicit I/O errors; do not use `Path::exists` to turn permission or malformed-state errors into absence. Reject any candidate referencing a tombstoned URL before promotion, with a safe external error. Recheck immediately before pointer replacement. A marker created in the final race still wins at Caddy.
2. Change `prepare_shared_media` to copy only `current` media, including first-publish migration, before promotion. `copy_release_media_to_shared` must check the tombstone before reading the source or touching the shared target: skip an intentionally denied artifact, but keep a missing or corrupt **untombstoned** manifest-listed artifact as an error. Preserve byte equality, WebP type/fingerprint checks, private `.media-staging` write, atomic target rename, and retention timestamp refresh for ordinary media. Remove candidate-to-shared copying and the cleanup loop that tries to retract already exposed candidate files.
3. After `promote_candidate` succeeds, copy the newly active `current` media to shared storage before pruning releases or shared files. Caddy's fallback serves a new URL during that copy. If this copy fails, leave `current` and retained releases untouched, report the existing privacy-safe post-promotion cleanup warning, and retry on the next publish or explicit operator repair. Do not report it as a pre-promotion failure or move a committed release to `failed`. Before a manual rollback while this warning exists, repair/verify the active release's shared media; otherwise the just-demoted URL could lose its 24-hour bridge. Keep the existing demoted-release refresh before deletion and age/reference rules for ordinary shared-media pruning.
4. Teach shared-media pruning to ignore tombstoned paths as retained references and remove any tombstoned shared copy regardless of age. Retained release pruning must skip reading intentionally removed bytes and proceed to remove eligible old releases and their private admin image maps. It must still fail safely on unrelated missing/corrupt bytes. A rollback target can retain tombstoned files, but Caddy must deny their URLs and no refresh may republish them.
5. Factor the precommit sequence so a unit test can invoke a controlled promotion callback at the exact point after active-media preparation and before `current` replacement. Assert candidate-only URLs are absent from shared and current at that callback, then inject promotion failure and assert the old pointer and media stay available while the candidate moves to failed retention. Extend the existing correction/rollback and failed-promotion integration tests; do not rely on a post-failure assertion alone to prove the pending interval.

**Deterministic cases:** precommit observer sees no candidate-only URL; forced promotion error leaves no candidate URL; pointer switch makes the new URL resolvable through `current/media` before shared copy; successful copy keeps both old/new URLs through correction, unpublish, rollback, and aggressive release pruning; injected post-commit copy failure leaves the new active URL reachable with a warning and preserves releases for retry; a tombstoned candidate fails before pointer change; a tombstoned missing file in a retained release does not block later release/shared pruning, while an untombstoned missing file does.

### 2. Deny tombstoned URLs before every origin fallback

**Files:** `deploy/ansible/roles/autographs_deploy/files/Caddyfile`, `controller/tests/caddy_static_routes.rs`, `scripts/verify-caddy-media-origin.sh` (new).

1. In **both** the public domain and loopback `http://:8081` `/media/*` handlers, use a named `file` matcher rooted at `/srv/autographs/static/.media-tombstones`, with `try_files {path}`. Place a `respond @tombstoned 404` before `root * /srv/autographs/static`, `try_files {path} /current{path}`, and `file_server` inside a `route` block so Caddy's normal directive sorting cannot move the deny behind either lookup. Keep the current `/media/*` cache header, shared-first resolution, and active-release fallback for other URLs. Require that the request path is evaluated before `try_files` rewrites it. The [official file matcher reference](https://caddyserver.com/docs/caddyfile/matchers#file) specifies its independent `root` and `try_files`; the [route reference](https://caddyserver.com/docs/caddyfile/directives/route) specifies literal handler order; the [try_files reference](https://caddyserver.com/docs/caddyfile/directives/try_files) specifies first-existing-file rewriting. Confirm the adapted configuration and actual HTTP statuses, not just text order.
2. Update the Rust Caddy contract test for two marker checks, two ordered denies, and unchanged shared/current fallback. Add the executable origin probe script. It must create a temporary static volume fixture with committed A and candidate B, run the repository Caddyfile with the existing `docker.io/library/caddy:2-alpine` image (or a local `caddy` binary), and request the loopback listener. Assert: A is 200; candidate-only B is 404 before pointer switch; B is 200 immediately after switch with no shared copy; A remains 200 through shared retention; a marker for B changes B to 404 even when both shared and current copies exist; removing the shared B copy still returns 404; A remains 200. Exercise the public-domain block as well, using a local hostname/Host header or Caddy adapter inspection plus deployed HTTPS request. Assert marker files themselves are not publicly retrievable. Clean up the temporary fixture and server; never point this probe at the live static volume. Combine this real Caddy precommit HTTP fixture with task 1's controlled local publisher callback as the precommit acceptance proof; no production pause or fault hook is required.

### 3. Make the emergency procedure durable and keep the live gate

**Files:** `docs/cdn-cache-contract.md`, `docs/static-artifact-contract.md`, `docs/static-runtime-runbook.md`.

1. Replace the pre-promotion candidate-copy description with the pointer-first sequence and describe the post-commit fallback/repair state. Explain the 24-hour origin retention as measured from last active publication, plus retained-release references, and its exact emergency exception. Keep HTML/JSON at 60 seconds, `/media/*` at 86,400 seconds, and routine Cloudflare no-purge behavior.
2. Document a takedown preflight **after publishing the unpublish if possible**. Resolve `STATIC_ROOT` with `sudo podman volume inspect autographs-static --format '{{.Mountpoint}}'` (or the deployed Ansible volume name). Run `sudo podman inspect --format '{{range .Mounts}}{{println .Name .Source .Destination .RW}}{{end}}' autographs-controller` and the same command for `autographs-caddy`; compare the named `autographs-static` volume and canonical source mountpoint at controller destination `/var/lib/autographs/static` (`RW=true`) and Caddy destination `/srv/autographs/static` (`RW=false`). Abort on any mismatch or absent mount. Validate the exact `/media/<slug>/<slug>-(thumbnail|detail)-<16 hex>.webp` URL with no traversal. The first mutating operator action is `sudo install -D -m 0644 /dev/null "$STATIC_ROOT/.media-tombstones/${MEDIA_URL#/}"`; it creates the durable marker before any origin-copy deletion. Read back that exact regular marker from Caddy's read-only mount with `sudo podman exec autographs-caddy test -f "/srv/autographs/static/.media-tombstones/${MEDIA_URL#/}"`. Probe **both** public origin HTTPS (bypassing Cloudflare with `curl --resolve`) and loopback `http://127.0.0.1:8081` for the exact URL; both must return 404. The successful Caddy readback and dual-route 404s, rather than host file creation alone, are the effective origin-deny commit evidence. If any check fails, stop and repair volume identity, mount visibility, or Caddy routing before deleting origin copies or purging CDN. After origin denial is proven, remove the exact path from shared media and every retained release, including active if necessary; purge only the exact Cloudflare URL and verify edge 404. A failed file deletion leaves the proven deny in force and can be retried. A failed CDN purge leaves a possible cached copy until purge or TTL expiry and must be escalated as incomplete takedown. Never remove a marker merely to restore a rollback; reinstate content only through an explicit separate decision and new fingerprint.
3. Keep the existing `controller/tests/live_static_publish_smoke.rs` assertions for adjusted old/new paths, privacy, unpublish document 404, and recent normal media 200. Run them against deployed Caddy with an origin cache miss and record statuses without exposing cookies or OCI identifiers. Do not make the routine smoke create permanent tombstones. Put the disposable tombstone and post-prune origin exercise in Wave 8's operator proof below.

### 4. Preserve the publish freeze through deployment

**Files:** `deploy/ansible/roles/autographs_deploy/defaults/main.yml`, `deploy/ansible/roles/autographs_deploy/tasks/main.yml`, `docs/static-runtime-runbook.md`, `controller/tests/caddy_static_routes.rs`.

1. Add an explicit Ansible `autographs_deploy_publish_frozen` switch, default `false`. When true, insert two exact-path Caddy `handle` blocks for `/admin/api/publish/full` and `/admin/api/publish/incremental`, returning `503` with `Cache-Control: no-store`; do not block `/admin/api/publish/status` or public static routes. Use an idempotent `ansible.builtin.blockinfile` task with a unique marker on the copied host Caddyfile, inserted inside the public-domain site block before the generic `/admin/api/*` proxy. Run it **after** the existing `copy` task but **before** `flush_handlers` so the live old Caddy config remains gated until the new frozen config restarts. Verify Caddy's adapted handler order. A later run with the switch false removes the block and restarts Caddy only after all readiness checks pass. Update the route test to check both frozen and normal rendered configurations and that publish-status remains accessible. If the gate cannot be preserved across the Ansible copy/restart sequence, stop the rollout.
2. Before replacing either running process, prepare the reviewed images/configuration and run local publisher plus containerized Caddy HTTP checks. On the VM, back up the installed Caddyfile, add the same two exact-path temporary `503` blocks to the **currently running** Caddy configuration, validate with `sudo podman exec autographs-caddy caddy validate --config /etc/caddy/Caddyfile`, and reload with `sudo podman exec autographs-caddy caddy reload --config /etc/caddy/Caddyfile`. Because the quadlet bind-mounts a single Caddyfile, edit that host file's inode in place for this initial freeze; an atomic host rename can leave the running container reading the prior inode. Verify both `POST` publish endpoints return `503` through the public admin origin while `/admin/api/publish/status` and `current` public pages still respond. Stop automated smoke/publish jobs and direct private-network calls to `autographs-controller:8080`; if any other publisher ingress exists, gate it as well or abort. After the gate is live, poll publish status and logs until no in-flight publish remains and record the unchanged `current` pointer. Keep Caddy running to serve the active release; do not stop the controller service as a shortcut because the current Caddy quadlet declares `Requires=autographs-controller.service`.
3. Deploy with `autographs_deploy_publish_frozen=true`, including the revised controller image and Caddyfile. Keep the temporary gate in the Ansible-rendered Caddyfile throughout both service restarts. Verify `autographs-controller.service` and `autographs-caddy.service` are active; inspect the controller container's running image digest against the intended revised build; validate/adapt the running Caddyfile; confirm the controller's normal authenticated status endpoint works; and exercise the marker HTTP fixture against **both** deployed Caddy routes while the gate remains active. Re-probe both publish POSTs for `503`, publish status for no running job, and current public documents/media for `200`. A failed check leaves the freeze in place; restore the last known-good current pointer or service image/configuration as needed without reopening publish.
4. Only after all revised-publisher and dual-route readiness checks pass, rerun the Ansible role with `autographs_deploy_publish_frozen=false` to remove the temporary gate. Verify both publish POSTs now reach the authenticated controller (unauthenticated probes must return `401`/`403`, never `503`, and must not start a job), `/admin/api/publish/status` works, and the existing current release remains served. Then explicitly release the operator freeze and allow credentialed publish/smoke activity. Record gate-on, deployment, readiness, and gate-off times and commands in the Wave 8 evidence. Never test unfreeze by issuing an authenticated publish before readiness.

**One-way operational checkpoint:** An emergency marker plus exact CDN purge intentionally breaks previously published URLs and should persist indefinitely. Require an explicit operator decision on the exact disposable or real URL before the Wave 8 takedown exercise; do not silently clear markers during test cleanup or rollback. There is no Oracle schema migration. Freeze publication before replacing either process, keep the freeze through the Caddy and controller restart, and resume only after both revised routes and the running controller pass readiness. Preserve the existing active/shared static volume, and reconcile any historically removed URLs into markers before the first new publish so retained-copy refresh cannot resurrect them. Treat deployment of a Caddy image that cannot parse the matcher as a stop condition, not a reason to publish without the deny.
