# PR #294: public media commit and emergency takedown contract

## Outcome and invariants

The reviewed source has locally resolved `CR-02` (`candidate_media_precommit_exposure`, a `CR-01` fix regression) and `WR-02` (`emergency_media_takedown_retention`, a sibling consumer miss). This revision addresses `CR-03`, the production-deployment sibling miss in the same `CR-02` family. Preserve the following release/media contract: an anonymously served `/media/*` response comes from an already committed release, except for a previously committed fingerprint retained for fresh documents and rollback. A candidate-only URL is absent before the `current` pointer changes, even if validation has passed or promotion fails. New active media is immediately reachable through Caddy's `current/media` fallback; old fingerprints remain available in shared media for at least 86,400 seconds after last active publication and while a retained release references them. An exact emergency tombstone overrides both serving locations and all retention or rollback copies. Candidate validation refuses a tombstoned URL before promotion. Public output remains free of private identifiers and adjustment metadata. Preserve the round 1 WebP byte/fingerprint and decoded-dimension checks (`WR-01`). Normal adjustment and unpublish retain the no-routine-Cloudflare-purge rule; emergency removal requires exact CDN purge.

The commit boundary is the existing atomic `current` symlink rename in `promote_candidate`. Candidate validation authorizes content, but the pointer change authorizes public visibility. Shared media is a retention namespace, never a candidate staging namespace. The durable marker mapping is `${AUTOGRAPHS_STATIC_RELEASE_ROOT}/.media-tombstones/media/<item-slug>/<image-slug>-<variant>-<16-hex-fingerprint>.webp` for exactly the requested `/media/...webp` URL. Marker files are empty regular files outside `current`, `releases`, `media`, and candidate manifests; no publisher cleanup deletes them. Both Caddy sites use the mounted static volume and test this path before shared or `current/media` lookup. Neither the marker path nor private release directory is web reachable.

Before a manual rollback while this warning exists, repair/verify the active release's shared media; otherwise the just-demoted URL could lose its 24-hour bridge. 4. Teach shared-media pruning to ignore tombstoned paths as retained references and remove any tombstoned shared copy regardless of age. 5. Factor the precommit sequence so a unit test can invoke a controlled promotion callback at the exact point after active-media preparation and before `current` replacement. Assert candidate-only URLs are absent from shared and current at that callback, then inject promotion failure and assert the old pointer and media stay available while the candidate moves to failed retention. Extend the existing correction/rollback and failed-promotion integration tests; do not rely on a post-failure assertion alone to prove the pending interval.

**Deterministic cases:** precommit observer sees no candidate-only URL; forced promotion error leaves no candidate URL; pointer switch makes the new URL resolvable through `current/media` before shared copy; successful copy keeps both old/new URLs through correction, unpublish, rollback, and aggressive release pruning; injected post-commit copy failure leaves the new active URL reachable with a warning and preserves releases for retry; a tombstoned candidate fails before pointer change; a tombstoned missing file in a retained release does not block later release/shared pruning, while an untombstoned missing file does.
