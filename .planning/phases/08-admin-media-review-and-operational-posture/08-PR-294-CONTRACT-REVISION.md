# PR #294: public media commit and emergency takedown contract

## Outcome and invariants

The reviewed source locally resolved `CR-02` (a `CR-01` candidate-visibility regression), `WR-02` (a takedown/pruning sibling), and `CR-03` (a production-deploy gate consumer); production rollout remains unproven. Round 4 found `CR-04`, another `CR-01` sibling in deployment reaudit, and `WR-03`, another `WR-02` sibling in active-file verification. Preserve the following release/media contract: an anonymously served `/media/*` response comes from an already committed release, including a previously committed fingerprint retained for fresh documents and rollback. A candidate-only URL is absent before the `current` pointer changes, even if validation has passed or promotion fails. New active media is immediately reachable through Caddy's `current/media` fallback; old fingerprints remain available in shared media for at least 86,400 seconds after last active publication and while a committed retained release references them. An exact emergency tombstone overrides both serving locations and all retention or rollback copies, and permits intentionally missing marked bytes. Candidate validation refuses a tombstoned URL before promotion. Public output remains free of private identifiers and adjustment metadata. Preserve the round 1 WebP byte/fingerprint and decoded-dimension checks (`WR-01`). Normal adjustment and unpublish retain the no-routine-Cloudflare-purge rule; emergency removal requires exact CDN purge.

The commit boundary is the existing atomic `current` symlink rename in `promote_candidate`. Candidate validation authorizes content, but the pointer change authorizes public visibility. Shared media is a retention namespace, never a candidate staging namespace. The durable marker mapping is `${AUTOGRAPHS_STATIC_RELEASE_ROOT}/.media-tombstones/media/<item-slug>/<image-slug>-<variant>-<16-hex-fingerprint>.webp` for exactly the requested `/media/...webp` URL. Marker files are empty regular files outside `current`, `releases`, `media`, and candidate manifests; no publisher cleanup deletes them. Both Caddy sites use the mounted static volume and test this path before shared or `current/media` lookup. Neither the marker path nor private release directory is web reachable.
