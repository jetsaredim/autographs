# Phase 07 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none |
| Icon library | none; use existing inline SVG only where already patterned |
| Font | Public: `"IBM Plex Sans", "Segoe UI", sans-serif`; admin: `"IBM Plex Sans", "Segoe UI", system-ui, sans-serif` |

Source: `AGENTS.md`, `.planning/phases/07-metadata-taxonomy-and-public-facets/07-CONTEXT.md`, `.planning/phases/06-admin-collection-workflow/06-UI-SPEC.md`, `controller/static-public/assets/site.css`, `controller/static-public/assets/browse.js`, and `controller/static-admin/*`.

Design-system contract:
- Keep Phase 7 on generated static public artifacts plus the existing Rust private controller/admin shell. Do not introduce React, Next.js, Vite, Tailwind, shadcn, a browser storage draft system, or a frontend build pipeline.
- Preserve the current public collection hide/reveal filter pattern and evolve the facet contents inside it. Do not redesign the public collection page shell.
- Preserve the current admin shell, tabs, grouped form sections, sticky save bar, and same-origin static HTML/CSS/JavaScript implementation.
- Render dynamic public/admin text through DOM node creation and `textContent` or server-side HTML escaping. Do not inject operator-controlled taxonomy values through raw HTML.
- Public artifacts and UI states must never expose Object Storage URLs, object keys, namespaces, bucket names, Oracle internals, image UUIDs, credentials, original filenames, unpublished records, or raw migration internals.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon glyph gaps, compact metadata pairs, selected-chip count offsets |
| sm | 8px | Label/input gaps, selected-filter chip gaps, signer-row action gaps |
| md | 16px | Default panel padding, form-grid gaps, facet-menu gaps, metadata group padding |
| lg | 24px | Page padding, section-to-section spacing, public filter-to-grid spacing |
| xl | 32px | Collection heading rhythm, admin header-to-content spacing, detail metadata breaks |
| 2xl | 48px | Public empty/error state padding and major public section breaks |
| 3xl | 64px | Public page-level spacing only; avoid inside admin taxonomy forms |

Exceptions:
- Minimum interactive target size is 44px by 44px for buttons, selects, inputs, filter chips, inline signer profile icon links, and icon-only filter toggles.
- Gallery cards keep a stable `4 / 5` media aspect ratio; facet additions must not resize cards after data loads.
- Admin textareas use a 96px minimum height for description/inscription and may use 64px only for short notes.
- Public/admin card and panel radius stays at 8px or less. Pill chips may use `999px` radius because they are repeated filter/status tokens.

## Typography

Use exactly these four type sizes and two weights in Phase 7 UI CSS.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.35 |
| Heading | 20px | 600 | 1.2 |
| Display | 32px | 600 | 1.1 |

Typography contract:
- Body copy, taxonomy values, signer names, item titles inside rows/cards, diagnostics, and history values use 16px/400.
- Labels, table headers, facet labels, chips, helper captions, and metadata field labels use 14px. Use 600 for labels and 400 for helper text.
- Section headings use 20px/600. Public page titles and admin first-screen title may use 32px/600.
- Do not scale font size with viewport width. Letter spacing is `0` except existing all-caps eyebrows may use `0.08em` maximum.
- Long signer names, franchises, product lines, set names, tags, URLs, and certification IDs must wrap without overlapping controls at 320px viewport width.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Public `#fbfaf7`; admin `#f7f8f6` | Page backgrounds and quiet empty space |
| Secondary (30%) | `#ffffff` | Panels, cards, forms, tables, metadata groups, detail surfaces |
| Accent (10%) | Public `#6f675c`; admin `#25636a` | Primary actions, selected filters, active tabs, focus outlines, selected image/status markers |
| Destructive | `#b42318` | Destructive actions only |

Accent reserved for: `Save item`, `Publish changes`, active admin tabs, selected public filter chips, public filter active-count badge, keyboard focus outlines, selected image marker, signer profile icon hover/focus state, and successful actionable status links. Do not use accent for every link, every border, decorative headings, passive counts, or raw taxonomy values.

Supporting colors:
- Public text primary: `#2f2f2d`; public text secondary: `#6b6861`; public border: `#dfd8cc`; public muted surface: `#f4f1ea`.
- Admin text primary: `#242826`; admin text secondary: `#626862`; admin border: `#d7ddd5`; admin muted surface: `#eef2ed`.
- Warning: `#9a6700` for duplicate-signer warnings, full rebuild caution, migration/backfill caution, cleanup warnings, and pending publish states.
- Success: `#1f7a4d` for healthy controller/provider states, saved-private success, publish success, and migration report completion.
- Diagnostic/code background: `#111827` with `#f9fafb` text only inside redacted `pre` blocks.

Color contract:
- Keep public pages warm and gallery-forward and admin pages quiet and operational.
- Do not introduce decorative gradients, gradient blobs, bokeh, dark slate theme, or a new one-note palette.
- Status must pair color with text such as `Warning`, `Likely duplicate`, `Saved privately`, or `Published`.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Save item |
| Empty state heading | No taxonomy matches yet |
| Empty state body | Adjust filters or return to the full collection. New signer, franchise, format, product line, and language facets appear after the next publish. |
| Error state | The collection facets could not be loaded. Refresh the page or return to the full collection. |
| Destructive confirmation | Merge signer: Merge these signer profiles and update linked items? Review the target profile first; this cannot be undone from the admin UI. |

Additional required copy:
- Public no results: `No autographs match those filters.`
- Public clear action: `Clear filters`
- Public full collection action: `View collection`
- Admin duplicate warning: `Possible duplicate signer. Review the existing profile before saving a new signer.`
- Admin signer create hint: `Type a name to create a new signer, or choose an existing signer.`
- Admin signer links hint: `Wikipedia and IMDb links are optional and appear only on public item detail pages.`
- Admin custom item label: `Custom item`
- Admin custom item hint: `Use for self-designed or self-printed pieces. Format and product line still describe what the item is.`
- Admin loose tags hint: `Use loose tags only for details that do not fit signer, franchise, product line, format, origin, language, role, or set.`
- Save success: `Saved privately. Publish changes when this taxonomy batch is ready for the public site.`
- Publish success: `Published. Public facets now reflect the saved taxonomy.`
- Full rebuild confirmation: `Run a full rebuild after schema or taxonomy migration changes. Continue?`
- Migration report CTA: `Review backfill report`
- Migration report empty: `No backfill issues found. Review the generated PL/SQL before applying live data changes.`

Copywriting rules:
- Use collector-facing nouns: signer, character, franchise, product line, format, set, language, origin, loose tags.
- Do not use `category` in new public UI copy except in migration/backfill review notes that explain legacy mapping.
- Do not expose `custom` as a cryptic raw tag. Public/admin copy says `Custom item` or `Origin: Custom`.
- Keep public card signer text compact: `A + B` for two signers; `A, B + N more` for three or more. Accessible labels and detail pages carry the full signer list.

## Public Facet Contract

Facet groups:
- Primary public filters: `Signer`, `Franchise`, `Product Line`, `Format`, and `Language`.
- Secondary public filters: `Origin`, `Role`, and `Tags`.
- Do not use `Category` as a new public facet. Legacy categories may appear only as migration/backfill evidence.

Collection filter layout:
- Keep the current `.collection-panel`, `.filter-toggle`, `.gallery-filters`, `.filter-menu`, `.selected-filters`, and `.filter-chip` pattern.
- The collapsed filter toggle remains a 44px icon button with active-filter count badge.
- On desktop, render primary filters in a dense grid that fits without horizontal scrolling. Secondary filters appear in the same revealed panel below primary filters, visually separated by a small label or grouped row.
- On mobile, filters stack to one column or two balanced columns without clipped labels. The revealed filter panel may grow taller than the current three-filter panel but must remain scroll-free for the expected eight facet controls at 320px width.
- Selecting filters updates URL query parameters and selected-filter chips. Query parameter names are semantic: `signer`, `franchise`, `productLine`, `format`, `language`, `origin`, `role`, and `tag`.
- Within one facet group, the first pass remains single-select. Different facet groups combine with AND. Multi-value item fields match when the item has the selected value.
- Clear chips remove one filter at a time. A `Clear filters` recovery action clears all active filters when there are no results.

Language facet:
- JSON, URLs, query params, labels, metadata, and accessible names use semantic text values: `English`, `Japanese`, and `Chinese`.
- Select options may render compact flag text for scannability, but each option and chip must include the language name in accessible text/title.
- Public detail pages hide `Language: English` by default and show non-default values such as `Language: Japanese` and `Language: Chinese`.

Public cards:
- Keep the image-forward card with stable media area and overlay text.
- Cards show compact signer text, not profile links.
- Cards may include no more than two lightweight taxonomy chips beneath or over the card if the existing visual density still holds. Preferred default: signer overlay only, with facets discoverable in filters and detail pages.
- Multi-signer item cards link to one physical item and match any selected signer.

Public detail:
- Detail pages show signer credits as a `Signers` metadata group with ordered rows.
- Each signer row shows display name and optional role/context when present.
- Wikipedia/IMDb links render as small site icon links beside the signer name on detail pages only, never as full URLs and never on collection cards.
- Inline site icon links must have 44px touch targets, visible focus, `aria-label` such as `Open Wikipedia profile for {name}`, and `rel="noopener noreferrer"` for external links.
- Hide boring defaults: `Language: English` and `Origin: Official`. Show meaningful non-defaults: `Language: Japanese`, `Language: Chinese`, and `Origin: Custom`.
- Continue hiding absent optional detail fields for description, inscription, event/source/location/year, certification, set, franchise, and product line.

## Admin Editor Contract

Top-level structure:
- Preserve the admin tabs: `Hub`, `Add item`, `Items`, `Publish`, and `Diagnostics`.
- The item editor uses exactly these primary sections in order: `Identity`, `Classification`, `Details`, `Publication`, `Images`, and `History`.
- `Identity` contains `Title`, `Characters`, and repeatable `Signers`.
- `Classification` contains `Format`, `Franchise`, `Product Line`, `Set`, `Language`, and `Custom item`.
- `Details` contains `Description`, `Inscription`, `Event`, `Source`, `Event location`, `Estimated year`, `Certification company`, `Certification ID`, and `Loose tags`.
- `Publication`, `Images`, and `History` preserve the Phase 6 behavior unless a field name must change for taxonomy clarity.

Signer entry:
- Signers render as repeatable rows. Each row has an existing/new signer typeahead input, optional item-specific role/context, and row actions.
- Selecting an existing signer reuses the profile. Typing a new name creates a signer record on save.
- New signer rows expose optional Wikipedia and IMDb URL fields behind an inline expansion, not as required primary fields.
- Near-duplicate warnings appear on save or before save when feasible. Warnings do not block deliberate creation, but the user must be able to choose the existing profile instead.
- Provide a minimal signer edit/merge repair path. Merge is destructive and uses the confirmation copy in the copywriting contract.

Taxonomy controls:
- `Format` is a required controlled select. Initial values include `Trading Card` and `Comic Book`; future physical formats may be added without changing the control type.
- `Custom item` is a checkbox defaulting to false and writes origin semantics. It is not a tag field.
- `Language` is a single-value select defaulting to `English`.
- `Franchise` is multi-value with inline suggestions from existing values and free entry for new values.
- `Product Line` is a single optional value with inline suggestions from existing values and free entry for new values.
- `Set` is optional free entry with suggestions from existing set names.
- `Characters` is repeatable/free-entry with suggestions from existing character values.
- `Loose tags` remains available but visually de-emphasized below first-class taxonomy fields.

Item finder:
- Existing item filters must update from legacy `Signer`, `Title`, `Category`, `Tag`, `Publication status`, and `Changes` toward `Signer`, `Title`, `Franchise`, `Product Line`, `Format`, `Language`, `Publication status`, and `Changes`.
- Result rows show title, compact signer list, format, franchise/product line summary, publication status, pending-change marker, image count, and last updated date.
- Row actions remain concise: `Edit item`, `View history`, and `Publish status`.

## Interaction Contract

Public browsing:
- Public filter state remains URL-backed and shareable.
- Browser back/forward restores all active filters and selected controls.
- If facets fail to load, show the error-state copy as page content with `Refresh` and `View collection` recovery paths.
- If no results match, keep the filter panel available, render selected chips, and show `Clear filters`.
- Public pages never require JavaScript for access to the generated item detail pages, but JavaScript may enhance filtering and image/detail reveal behavior.

Admin save/publish:
- Saving taxonomy changes writes only to the private source of truth. It never publishes automatically.
- After save, keep the user on the item and show the same next actions as Phase 6: add another item, upload/manage images, publish changes, and return to hub.
- Publishing public facets remains an explicit action. Structural taxonomy/schema changes require full rebuild guidance and confirmation.
- Validation failures move focus to the first invalid field and preserve unsent values.
- Duplicate-signer warnings keep the form editable and place focus on the warning summary when generated after save attempt.

Migration/backfill review:
- Admin/operator-facing migration review UI, if included, is a diagnostics-style report surface rather than a routine editor panel.
- Backfill report rows distinguish `Mapped`, `Needs review`, and `Report only`.
- Report-only likely duplicate physical items are not auto-merged.
- The UI may link to generated operator artifacts by safe filenames only. It must not render Oracle connection strings, private object identifiers, or live credential material.

Destructive/irreversible actions:
- Signer merge requires confirmation naming the source profile and target profile.
- Image removal keeps the existing Phase 6 confirmation and cleanup behavior.
- Full rebuild keeps the existing warning confirmation and must explain it is for schema/taxonomy migration or repair.

## State And Accessibility Contract

Required public states:
- Facets loading, facets loaded, facets failed.
- No active filters, active filters, no matching results.
- Single-signer card, two-signer card, three-or-more signer card.
- Detail with optional signer links, detail without signer links.
- Default language/origin hidden, non-default language/origin visible.

Required admin states:
- Empty signer row, existing signer selected, new signer typed, duplicate warning, merge confirmation, merge success, merge failed.
- Format missing, language defaulted, custom item checked/unchecked.
- Suggested value selected, new taxonomy value typed, loose tag added.
- Migration report loading, report ready, report has review items, PL/SQL generation unavailable/error.
- Save pristine, dirty, saving, saved, validation failed, save failed, pending publish, publishing, publish failed.

Accessibility rules:
- Every input has a visible label.
- Repeatable signer rows announce their row number and current signer name where present.
- Typeahead/suggestion controls must be keyboard reachable and usable without pointer input.
- Icon-only controls and external profile links must have `aria-label`; site icons also need visible focus outlines.
- Public filter toggle keeps `aria-expanded`, `aria-hidden`, and inert behavior aligned with the existing implementation.
- Status messages use `role="status"` for non-critical updates and `role="alert"` for blocking validation/errors.
- Focus-visible outline uses the relevant accent color at 2px with 3px offset.
- Color is never the only status signal.
- Text must fit without overlap at 320px, 760px, 980px, and 1200px viewport widths.
