## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin client -> controller JSON | Operator-entered signer/taxonomy values enter trusted Rust validation. |
| Controller -> Oracle | Validated metadata becomes durable relational data with constraints. |
| Legacy data -> Phase 7 schema | Existing `signer`, `category`, and tags remain readable references during migration. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01-01 | Tampering | `AutographItemInput` / `AutographItemUpdate` | mitigate | Validate nonempty `title`, nonempty signer credits, nonblank `format`, allowed `origin`, allowed `language`, bounded URL fields, and duplicate signer-credit rejection in `catalog.rs`. |
| T-07-01-02 | Information Disclosure | `controller/db/updates/07-01-taxonomy-schema.sql` | mitigate | Keep schema scripts free of live Oracle credentials, Object Storage identifiers, object keys, and production data values. |
| T-07-01-03 | Denial of Service | Oracle schema preflight | mitigate | Fail closed on missing Phase 7 tables/columns instead of running with partial signer/taxonomy state. |
| T-07-01-04 | Repudiation | Edit history diffs | mitigate | Record field diffs for signer credits and taxonomy arrays so metadata changes remain reviewable under DATA-03. |
| T-07-01-SC | Tampering | Package supply chain | mitigate | Do not add new Rust/npm packages in this plan; if a dependency becomes unavoidable, stop and add a package legitimacy checkpoint before installation. |
</threat_model>
