# Static Public Artifact Contract

## Purpose

The public autograph catalog is generated inside the OCI runtime boundary and
served as static output. GitHub Actions builds and deploys code artifacts only.
It never reads Oracle catalog content, private Object Storage metadata, or
private media, and it never generates catalog content.

The current public contract uses `schemaVersion: 2`; this is the schemaVersion 2
public artifact contract. Public artifacts are
display and filtering DTOs, not serialized database rows.

## Selected Shape

Phase 5 uses split collection data plus per-item detail JSON:

| Artifact | Path | Purpose |
|----------|------|---------|
| Collection page | `/collection/index.html` | Static gallery shell |
| Shared stylesheet | `/assets/site.css` | Static copy of the public visual system |
| Favicon | `/favicon.ico` | Browser tab icon copied from the original app |
| App icon | `/icon.png` | PNG icon used by modern browsers and touch icons |
| Architecture page | `/architecture/index.html` | Static copy of the public architecture/about route |
| Architecture diagram | `/architecture/architecture-diagram.svg` | Static architecture diagram asset |
| Collection data | `/data/collection.json` | Gallery cards and primary image variants |
| Facets | `/data/facets.json` | Signer, franchise, product line, format, language, origin, role, and tag filtering values |
| Item page | `/items/{item-slug}/index.html` | Static item detail shell |
| Item detail data | `/data/items/{item-slug}.json` | Full public-safe item detail DTO |
| Publish manifest | `/manifest.json` | Release ID, generation timestamp, artifact paths, and byte sizes |
| Generated media | `/media/{item-slug}/{image-slug}-{variant}-{derivative-fingerprint}.{ext}` | Public thumbnail and detail derivatives |

The 500-item fixture profiles three shapes:

| Shape | Bytes | Notes |
|-------|------:|-------|
| Single detail JSON | 677,361 | Smallest transfer, but requires full detail regeneration for routine changes |
| Split collection plus per-item details | 946,749 | Selected: supports explicit incremental item publishing |
| Hybrid collection plus detail bundle | 947,250 | Similar size without the per-item update advantage |

The selected split is not the smallest byte count. It is the simplest shape
that preserves browse/filter behavior while allowing an item update to replace
one detail artifact and the affected indexes.

Stable shell pages and browser assets are copied from `controller/static-public/`
when a release is generated. Per-item detail pages are rendered from the
publisher detail template because their content varies with catalog records.

## Versioning

`collection.json`, `facets.json`, each item detail JSON artifact, and
`manifest.json` contain `schemaVersion: 2`.

Contract changes that break an existing static reader require a schema version
increment and a full rebuild. Additive fields may remain within a version when
old readers can safely ignore them.

`manifest.json` may include an additive `generator` object with the repo
version, deployed controller version, semver-tagged controller image, and source
revision that generated the release. This identifies the controller/static publisher version
behind a live static release without exposing private Oracle or Object Storage
coordinates.

## Public DTO Rules

Gallery DTOs contain:

- Public item slug, title, `signerText`, `signerNames`, `signerRoles`,
  `signers`, `characters`, `franchises`, `productLine`, `setName`, `format`,
  `origin`, `language`, and secondary `tags`.
- Compact signer text for collection cards and the complete signer list for
  accessible labels and detail views.
- An optional primary image with public derivative variants.

Detail DTOs add:

- Public derivative images.
- Display-oriented detail groups.
- Full signer credit rows, including optional role/context values and optional
  public-safe signer profile links for Wikipedia or IMDb. Collection cards do
  not expose those external profile links.

Facet DTOs contain:

- Facet groups with ids `signer`, `franchise`, `productLine`, `format`,
  `language`, `origin`, `role`, and `tag`.
- Category is not a schemaVersion 2 facet. Legacy `category` values may remain
  in Oracle for rollback/reference during Phase 7, but generated public facets
  come from the schema version 2 taxonomy fields.

Manifest entries contain:

- Public artifact path.
- Generated byte size.

## Media Paths

Public derivatives use sanitized deterministic paths:

```text
/media/{item-slug}/{image-slug}-thumbnail-{derivative-fingerprint}.webp
/media/{item-slug}/{image-slug}-detail-{derivative-fingerprint}.webp
```

The path is independent from the private original filename, private Object
Storage key, private image UUID, and saved image adjustment. The fingerprint is
derived from the final public WebP bytes after applying a saved adjustment and
resizing. A correction therefore changes both thumbnail and detail URLs even
when the private original is unchanged. The collection and detail JSON and
rendered detail HTML refer to the new paths after normal publish; each URL is a
distinct edge-cache object, so routine corrections need no Cloudflare purge.
Thumbnail and detail derivatives are generated output and may be rebuilt from
durable private originals. Internal schema v2 derivative cache metadata binds
the source, transform version, canonical adjustment, variant, and verified WebP
payload digest before reuse.

Caddy serves public `/media/*` from a stable shared directory. The publisher
copies validated media there before changing the `current` release pointer and
migrates any already active release media on the first publish. Shared media
retains old and new fingerprints through cached-document freshness and rollback:
at least 24 hours after last active publication, plus any URLs referenced by
retained releases. The active candidate and its manifest still contain only
currently published media. A routine unpublish removes its page and JSON, but
its known old derivative URL remains fetchable until retention ends. Emergency
privacy takedown requires removal of retained origin copies and an exact CDN
purge; see [cdn-cache-contract.md](cdn-cache-contract.md).

## Privacy Deny-List

Public JSON, HTML, manifests, and media paths must not contain:

- `storageNamespace`
- `bucketName`
- `objectKey`
- Object Storage URLs or the string `objectstorage`
- OCI configuration keys such as `OCI_`
- Oracle connection details
- Private image UUIDs
- Original filenames
- Saved adjustment JSON, crop/perspective coordinates, and private media revision

The Rust static contract tests generate a 500-item, multi-image fixture and scan
the rendered public artifact set for these values.

## Publishing Boundary

Catalog generation runs in the private controller inside the OCI/runtime
boundary. A release is generated as a complete candidate, validated for
artifact presence and privacy, and promoted only after validation passes.

GitHub Actions may build and deploy controller code or container images. It
must not connect to Oracle, inspect private Object Storage originals, receive
private bucket details, or publish catalog content.
